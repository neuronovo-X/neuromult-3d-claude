# Текстуры: живописная стилизация референса против нашей реализации и процедурный рендеринг

> Тематическая директория: `references/textures/` (скрипты анализа, кропы, числовые датасеты, сопоставления, процедурные прототипы). 
> Все замеры выполнены локально на материале эталонных анимационных шотов и тестовых рендеров Remotion.

---

## 0. Главные выводы (Bottom line)

В эталонном художественном стиле (референсе) каждая поверхность решена несколькими локальными плоскими цветовыми полями с мягкими растяжками. Нарисованные текстурные линии (щели между досками, кладочные швы, стыки черепицы) исключительно тонкие — около 3–5 px в разрешении 1080p. Освещенные солнцем участки и тени укладываются в узкий, яркий и насыщенный диапазон; тональная вариативность присутствует только на уровне крупных форм.

Наши текущие процедурные поверхности расходятся с эталоном по пяти ключевым пунктам:

1. **Слишком темные.** Наш настил рендерится со светлотой L* 50, тогда как референс дает L* 72–80. Металл и боковые балки проваливаются в L* 3–7, тогда как в референсе тени никогда не опускаются ниже L* 19.
2. **Слишком блеклые.** Наше небо имеет насыщенность C* 22–29 против эталонных C* 40–89. Наше закатное «золотое» небо превращается в серо-лиловую кашу с C* 16–19.
3. **Линии слишком широкие и размытые.** Зазоры между досками и известковый раствор в 1.5–2.5 раза шире нормы, а ширина их краевого спада (10–90 %) составляет 4–6 px.
4. **Неверная структура воды.** Гребни и рябь покрывают равномерные 4–12 % площади, формируя вертикальные полосы в ракурсах вдоль реки; отсутствует градиент глубины по углу наклона камеры.
5. **Плоские облака.** Наша реализация использует однотонную заливку. В референсе всегда читаются три тона с характерным лавандово-голубым основанием.

Все приведенные ниже параметры строго измерены. Процедурный рецепт из раздела 5 прошел проверку типов TypeScript, а сгенерированные карты воды и настила протестированы в CPU-превью на полное соответствие эталонным метрикам (раздел 5.6).

## 1. Методология измерений

- **Референс:** 91 кадр из 14 видеороликов (01, 02, 03, 04, 05, 07, 08, 10, 11, 12, 13, 14, 18, 19), маркированных по схеме `VV_SS.s` (номер видео, секунда).
 Подготовлено 99 кропов из 13 видеороликов: в исходном разрешении в каталоге `crops/`, с масштабированием 2x в `crops/x2/`, а также 30 детализированных макро-кропов (`crops/z_*`).
 Замеры охватывают 79 + 14 патчей поверхностей (`data/patches*.json`), 40 профилей линий (`data/lines.json`), 11 водных бассейнов, 17 вертикальных срезов неба и 11 срезов облаков.
- **Наша сцена:** 61 тестовый статичный кадр из `your Remotion project/out/bridge/test/` (превью JPEG 540x960, только чтение).
- **Масштабная сетка:** все размеры в пикселях приведены к единому базовому кадру 1080x1920. Кадры референса (исходно 720p) масштабированы с коэффициентом x1.5, а наши превью — x2.
 Поскольку наши превью сохранены в половинном разрешении, измеренная ширина контуров включает порядка 2 px апскейл-размытия. При расчете оптического увеличения текстур (M) эта погрешность вычиталась.
- **Субтитры:** в эталонных видео полоса текстовых плашек занимает строки 874–934 из 1280. Скрипт `scripts/captions.py` автоматически их детектирует (`data/captions.json`). При анализе воды строки 760–952 маскировались. Три тестовые области, задевавшие субтитры, были скорректированы и перемерены заново (трава 12_57.5, металл 12_52.5, край пирса 05_40.5).
- **Цветовое пространство:** шестнадцатеричные значения (hex) даны в sRGB. Параметры светлоты L* и цветности/хромы C* рассчитаны в CIE Lab (D65). «Кластеры» вычислены методом k-means (k = 4 в Lab) в формате `цвет : процент площади`. FWHM (полная ширина на полувысоте) темной нарисованной линии замерена перпендикулярно оси линии по полосовым медианам. «Край» (Edge) — ширина перехода 10–90 % на склоне линии.
- **Инструментарий анализа** (все скрипты в каталоге `textures/scripts/`):
 - `extract.py`, `crops.py`, `mosaic.py` — извлечение кадров, нарезка фрагментов и сборка атласов.
 - `measure_patches.py` и `tm.py` — замер цвета, шума и доли линий.
 - `lines.py` и `lines_batch.py` — профилирование ширины линий, резкости краев и глубины контраста.
 - `profile.py` — профили поперечного сечения досок, `water.py` — рябь и градиенты воды, `sky.py` — градиенты неба, `clouds.py` — тон и форма облаков.
 - `sidebyside.py` — генерация сравнительных листов сопоставления.

- **Базовый градиент:** чистая, насыщенная вертикальная растяжка. У горизонта вода светлее и с выраженным циановым оттенком; по направлению к камере становится темнее, глубже и синее. Перепад светлоты от горизонта к ближнему краю составляет 10–35 единиц L*.

**Ключевые ошибки нашей сцены:**
- Нет градиента глубины по лучу зрения.
- Рябь у камеры в 2–10 раз плотнее, чем в референсе.
- В ракурсах сбоку штрихи превращаются в вертикальные полосы (пропорция 0.7), так как штрихи длиной 30–100 px ориентированы вдоль оси u и встают торцом к камере.
- На закате вода становится тусклой грязно-серой (C* 14), тогда как в референсе закатная вода сохраняет сочную насыщенность: синий #4482b3 или глубокий фиолетово-синий #262246.

## 4. Плотность текселей (Texel density)

Экранная плотность пикселей для нашей оптики рассчитывается по формуле: 
`px/m = 1920 / (2 · D · tan(18°)) = 2954 / D` 
(при вертикальном угле обзора vfov 36° на кадре 1080x1920 для поверхности, перпендикулярной лучу зрения). 
Для наклонных поверхностей вдоль оси глубины значение умножается на `sin(угла скольжения)`.

| Дистанция D (м) | 0.5 | 1 | 2 | 5 | 10 | 20 | 50 | 100 |
|---|---|---|---|---|---|---|---|---|
| Экранное разрешение (px/m) | 5908 | 2954 | 1477 | 591 | 295 | 148 | 59 | 30 |

**Анализ эталонного увеличения (магнификации M).** По ширине спада нарисованных границ (10–90 %) после вычета артефактов масштабирования 720p-видео рассчитано экранное увеличение текстуры (экранных пикселей на один тексель):
- спад границы 10–90 % ≈ `sqrt((0.8 M)² + 1.5²)`;
- раствор кладки и сайдинг: M ≈ 2–3;
- зазоры между досками на переднем плане: M ≈ 3.7;
- экстремально крупный план палубы (01_50.5): M ≈ 5.7.

В референсе текстуры увеличиваются в диапазоне 2–6 px на тексель и никогда не превышают этот порог. 
**Целевой стандарт:** `M ≤ 6` на минимальной дистанции фокусировки, `M ≤ 3` на типовых рабочих расстояниях. 
Требуемая плотность текстуры: `texels/m = (px/m) / M`.

## 5. Рецепт процедурной реализации (Стек: Three.js 0.175, Lambert-материалы, CanvasTexture через `ctex`)

Все процедурные генераторы собраны в файле `proto/paint_recipe.ts` и приведены целиком в Приложении. Они используют функции `ctex(key, w, h, (g, r) =>...)` и `rng` в точности так же, как в текущем `paint.ts`, без привлечения растровых картинок извне. Код успешно проходит строгую валидацию `tsc --strict`. 
Для интеграции в рабочий проект достаточно перенести вспомогательные утилиты (`U`, `wrapX`, `wrap2`, `rr`, `blotch`, `grain`, `nail`) и сами генераторы в файл `src/videos/bridge/paint.ts`, переключив импорт на локальные `ctex` / `rng`. Все генераторы бесшовно тайлятся по горизонтали (ось x), а точечные маркеры также зацикливаются и по вертикали (ось y).

## 6. Топ-5 изменений по визуальному влиянию

1. **Градиент неба (шейдер в `world.ts` + высотные точки `SKY`).** Небо занимает 20–35 % площади большинства общих планов. У нас насыщенность вдвое ниже эталона (C* 22–29 против 40–89), а золотой час заваливается в серую грязь (C* 16–19). Внедрение 4 высотных точек вернет сочный дневной зенит #3d95ee, а закат проведет через чистые коралловые и сиреневые тона.
2. **Вода реки (шейдер + генераторы `waterNear` / `waterFar`).** Водная гладь покрывает 20–40 % кадров с мостом. Три обязательных шага:
 - градиент по углу депрессии луча (темная глубина у камеры, светлая бирюза у горизонта);
 - редкие горизонтальные штрихи гребней и впадин, закономерно исчезающие к переднему плану (1.6 / 1.0 / 0.8 %, а не монотонные 4–12 %);
 - ликвидация вертикальных полос в ракурсах вдоль реки.
 Закатная вода должна быть насыщенной фиолетово-синей, а не серым пятном #213b4e.
3. **Доски настила (`planksHD` + исправление UV настила).** Поднять светлоту освещенных досок до L* 72–80 (сейчас 50). Сузить зазоры вдвое и сделать их контрастнее (~4 % от шага доски). Добавить световую и теневую фаски на кромках. Рисунок волокон ни в коем случае не должен считываться как щель. Плотность 1024 texels/m гарантирует отсутствие пикселизации даже на объективе 0.5 м.
4. **Камень (`stoneHD` для башен, парапетов и набережной, `cobbleHD` для мостовой).** Переход на нейтральные светлые блоки (C* ~10, L* ~75 на солнце). Раствор сделать на треть уже и существенно светлее (ΔL* ~18, а не черная канава #503f26). Вместо сетки «в горошек» вымостить набережную перевязанными прямоугольными брусками.
5. **Вывод металла и дерева из черного провала (`M.iron` #4b5468, `chainHD`, `beamHD`, светлый `beam()`).** Подвесные цепи, якоря и боковые балки моста сейчас имеют L* 3–7. В референсе металл и тени никогда не опускаются ниже L* 19 (за исключением контурной туши). Именно широкие нарисованные полосы бликов формируют ощущение честного металла в стилистике 2D-анимации.

Следующие по приоритету:

## 7. Ограничения и нюансы калибровки

- Наши тестовые кадры — превью JPEG в разрешении 540p. Измеренные параметры краев содержат около 2 px апскейл-размытия, поэтому финальный рендер в 1080p будет чуть четче тестовых цифр. На цветовые замеры это не влияет.
- Итоговый цвет на экране формируется взаимодействием текстурного альбедо, источников света и пост-грейдинга. В приведенных процедурных генераторах значения альбедо откалиброваны под текущий дневной свет (плоский настил под ним дает множитель ~x0.93–1.03 по линейным каналам). Если настройки освещения изменятся, ориентируйтесь на экранные таргеты и корректируйте альбедо.
- В эталонных материалах отсутствуют булыжная мостовая и подвесные цепи. Соответствующие процедурные рецепты спроектированы по общим канонам стиля (плоские локальные тона, тонкие светлые швы, живописные бликовые полосы).
- CPU-превью не включают мипмапы и динамический свет Three.js. Финальную верификацию необходимо производить на честных рендерах (раздел 5.5).

## Приложение: процедурные генераторы `proto/paint_recipe.ts`
*(Проверено компилятором TypeScript: `tsc --strict`; в проекте функции `ctex` и `rng` импортируются из `./paint`)*


```ts
// Процедурные рецепты текстур для анимационного шота: Canvas2D генераторы в стиле reel-kit/src/videos/bridge/paint.ts
// (ctex + rng, без внешних растровых изображений). Прототип для проверки; в рабочем проекте переносятся в paint.ts
// рядом со старыми генераторами (строка импорта заменяется на локальный `./paint`).
// Числа в комментариях соответствуют эталонным замерам из reports/textures.md.
// Все линейные размеры предполагают указанные UV-масштабы.
import { ctex, rng } from "./shim";

type R = () => number;
type G = CanvasRenderingContext2D;
const pick = <T,>(r: R, a: T[]) => a[Math.floor(r() * a.length) % a.length];
const U = (r: R, a: number, b: number) => a + (b - a) * r();
const TAU = Math.PI * 2;

/** Выполнение fn в координате x и повтор со сдвигом на тайл при пересечении границы [x, x + w] (бесшовный тайлинг по x) */
const wrapX = (W: number, x: number, w: number, fn: (x: number) => void) => {
 fn(x);
 if (x + w > W) fn(x - W);
 if (x < 0) fn(x + W);
};
/** Аналогичное бесшовное дублирование для точечного элемента радиуса rad по обеим осям x и y */
const wrap2 = (W: number, H: number, x: number, y: number, rad: number, fn: (x: number, y: number) => void) => {
 for (const ox of [0, -W, W]) for (const oy of [0, -H, H]) {
 const X = x + ox, Y = y + oy;
 if (X + rad > 0 && X - rad < W && Y + rad > 0 && Y - rad < H) fn(X, Y);
 }
};
/** Контур скругленного прямоугольника */
const rr = (g: G, x: number, y: number, w: number, h: number, k: number) => {
 k = Math.max(0, Math.min(k, w / 2, h / 2));
 g.beginPath();
 g.moveTo(x + k, y);
 g.arcTo(x + w, y, x + w, y + h, k); g.arcTo(x + w, y + h, x, y + h, k);
 g.arcTo(x, y + h, x, y, k); g.arcTo(x, y, x + w, y, k);
 g.closePath();
};
/** Мягкое эллиптическое пятно (радиальный градиент), растянутое с коэффициентом sx по оси x */
const blotch = (g: G, x: number, y: number, rad: number, sx: number, rgb: string, a: number) => {
 g.save(); g.translate(x, y); g.scale(sx, 1);
 const gr = g.createRadialGradient(0, 0, 0, 0, 0, rad);
 gr.addColorStop(0, `rgba(${rgb},${a})`); gr.addColorStop(1, `rgba(${rgb},0)`);
 g.fillStyle = gr; g.fillRect(-rad, -rad, rad * 2, rad * 2);
 g.restore();
};
/** Протяженный мягкий штрих древесного волокна вдоль оси +x; случайные смещения генерируются единожды для совпадения на границах тайла */
const grain = (g: G, r: R, W: number, x: number, y: number, len: number, amp: number, lw: number, col: string) => {
 const n = Math.max(2, Math.round(len / 180));
 const dy = Array.from({ length: n + 1 }, () => (r() - 0.5) * 2 * amp);
 wrapX(W, x, len, (xx) => {
 g.strokeStyle = col; g.lineWidth = lw; g.lineCap = "round";
 g.beginPath(); g.moveTo(xx, y + dy[0]);
 for (let i = 1; i <= n; i++) {
 const x1 = xx + (len * i) / n;
 g.quadraticCurveTo(x1 - len / n / 2, y + (dy[i - 1] + dy[i]) / 2 + (i % 2 ? 0.3 : -0.3) * amp, x1, y + dy[i]);
 }
 g.stroke();
 });
};
/** Шляпка гвоздя или болта с нарисованным светлым бликом (в референсе: темные точки с белым отблеском) */
const nail = (g: G, x: number, y: number, rad: number, col = "#3a2212") => {
 g.fillStyle = col; g.beginPath(); g.arc(x, y, rad, 0, TAU); g.fill();
 g.fillStyle = "rgba(255,240,215,0.55)"; g.beginPath(); g.arc(x - rad * 0.32, y - rad * 0.32, rad * 0.36, 0, TAU); g.fill();
};

// ---------------------------------------------------------------------------------------------------------------
/** Верх настила, поперечные доски. 2048 px = 2 м x 2 м (1024 texels/m: объектив 0.5 м дает увеличение ~5.8 px на
 * тексель, что соответствует самому крупному плану палубы в референсе, спад границы 10-90 % ~4.8 px при 1080p).
 * Ось y холста направлена вдоль моста (z): 8 досок по 0.25 м = 256 px. world.ts deckTop uv -> [0, z / 2, 2.5, z / 2].
 * Референс: разброс L* от доски к доске 1.2-4.2 (у нас 5-6), внутри доски 1.3-2.6, щели ~4 % от шага (FWHM) темно-коричневые
 * #571e00-#6b2903 (dL* 40-48), освещенная кромка +4..7 L*, теневая фаска -3..-6 L*, шляпки гвоздей и редкие сучки. */
export const planksHD = () => ctex("planksHD", 2048, 2048, (g, r) => {
 const S = 2048, B = 256, GAP = 8;
 // альбедо: при текущем дневном свете освещенные доски должны давать на экране L* 72-80 (в референсе #f8bb60, #dea04b,
 // #cd9a66); если в рендере они темнее, увеличьте эти значения (вплоть до #ffd08a) до корректировки источников света
 const fills = ["#efbd82", "#e8b47a", "#f4c58b", "#e3ae74", "#ecb97e"];
 for (let i = 0; i < 8; i++) {
 const y = i * B;
 g.save(); g.beginPath(); g.rect(0, y, S, B); g.clip();
 g.fillStyle = pick(r, fills); g.fillRect(0, y, S, B);
 for (let k = 0; k < 5; k++) { // широкий дрейф тона вдоль доски, +-2 L*
 const x = U(r, 0, S), rad = U(r, 120, 260), light = r() > 0.5;
 wrapX(S, x - rad * 3, rad * 6, (xx) => blotch(g, xx + rad * 3, y + B / 2, rad, 3, light ? "255,236,200" : "150,90,40", light ? 0.12 : 0.08));
 }
 for (let k = 0; k < 10; k++) { // волокна: длинные, тонкие, низкоконтрастные; никогда не должны быть темными как щели
 const light = r() < 0.3;
 grain(g, r, S, U(r, 0, S), y + U(r, 16, B - 16), U(r, 500, 1500), U(r, 2, 7), U(r, 1.5, 3.5),
 light ? "rgba(255,238,205,0.14)" : "rgba(140,82,36,0.13)");
 }
 if (r() < 0.35) { // сучок, встречается примерно на каждой третьей доске
 const kx = U(r, 120, S - 120), ky = y + U(r, 70, B - 70), rx = U(r, 14, 24), ry = rx * U(r, 0.45, 0.6);
 g.strokeStyle = "rgba(140,82,36,0.20)"; g.lineWidth = 2;
 g.beginPath(); g.ellipse(kx, ky, rx * 2.3, ry * 1.9, 0, 0, TAU); g.stroke();
 g.fillStyle = "rgba(150,88,38,0.30)"; g.beginPath(); g.ellipse(kx, ky, rx, ry, 0, 0, TAU); g.fill();
 g.strokeStyle = "rgba(105,55,22,0.55)"; g.lineWidth = 2.5; g.stroke();
 }
 for (let k = 0; k < 3; k++) blotch(g, U(r, 100, S - 100), y + U(r, 40, B - 40), U(r, 40, 110), 1.6, "120,70,30", 0.06); // следы износа
 // кромки доски: освещенная фаска с одной стороны, мягкое затенение с другой
 g.fillStyle = "rgba(255,238,200,0.35)"; g.fillRect(0, y + GAP / 2 + 1, S, 3);
 const sh = g.createLinearGradient(0, y + B - GAP / 2 - 18, 0, y + B - GAP / 2);
 sh.addColorStop(0, "rgba(80,35,10,0)"); sh.addColorStop(1, "rgba(80,35,10,0.24)");
 g.fillStyle = sh; g.fillRect(0, y + B - GAP / 2 - 18, S, 18);
 // один стык плашек на доску со смещением, прибит гвоздями с обеих сторон; гвозди на балках через каждый 1 м
 const jx = U(r, 90, S - 90);
 g.fillStyle = "#66300f"; g.fillRect(jx - 3, y, 6, B);
 g.fillStyle = "rgba(255,238,200,0.30)"; g.fillRect(jx + 3, y, 2, B);
 for (const nx of [jx - 24, jx + 24]) for (const f of [0.28, 0.72]) nail(g, nx, y + B * f, 5);
 for (const nx of [512, 1536]) for (const f of [0.3, 0.7]) nail(g, nx + U(r, -3, 3), y + B * f, 5);
 g.restore();
 }
 for (let i = 0; i <= 8; i++) { // щели рисуются поверх: ядро 8 px + мягкая окантовка 1 px = ~4 % от шага плашки 256 px
 g.fillStyle = "rgba(102,48,15,0.5)"; g.fillRect(0, i * B - GAP / 2 - 1, S, GAP + 2);
 g.fillStyle = "#66300f"; g.fillRect(0, i * B - GAP / 2, S, GAP);
 }
});

 g.fillStyle = "rgba(255,230,200,0.22)"; g.fillRect(x + 2, y + 2, w - 4, 2);

 for (let fl = 1; fl < floors; fl++) timberBeam(0, H - m(fl * 2.8) - t / 2, W, t);

 }

/** Рябь на реке в виде DATA-текстуры для шейдера воды (world.ts): R = гребень, G = впадина, B = блик; 1024 px = 8 м.
 * Два инстанса: редкий для ближнего плана и плотный с тайлингом 40 м для дальнего плана, поскольку в референсе рябь редеет
 * по направлению к камере (доля вдали 1.5-5 %, посередине 0-1.6 %, вблизи 0-0.9 %; у нас было 4-12 % повсеместно).
 * Эталонные штрихи: ширина 12-30 px при 1080p (p90 36-97), высота 3-6 px, пропорция 3-6, гребень +8..+13 L* с темной впадиной
 * -8..-9 L* строго под ним, тонкие бликовые нити 1-3 x 30-100 px. Штрихи представляют собой короткие, глубокие дуги со случайной
 * ориентацией (изотропные в среднем): перспективное сокращение само формирует горизонтальные черточки при ЛЮБОМ ракурсе камеры
 * (пропорция 1 / sin(угла скольжения) = 3.4 при 17 град, 5.8 при 10 град); в старой версии рисовались полосы 30-100 px вдоль оси u,
 * которые превращались в вертикальные полосы при взгляде вдоль русла реки. В Three.js обязательно: colorSpace = THREE.NoColorSpace. */

 };

});

/** Высотные цветовые ступени неба (в градусах) для 4-точечного шейдера в world.ts. Значения представляют собой целевые
 * экранные цвета (контролировать после финального грейдинга): эталонный день C* 40-89 (#208cfb, #0b6ced, #5ba8f0 -> #82c4fc),
 * у нас было C* 22-29 (#8ab6e7); эталонный закат C* 40-67 через коралловый / розовый / сиреневый, у нас было C* 16-19 пыльно-лиловый
 * из-за прямого смешивания синего и оранжевого через серую зону спектра. */
export const SKY = {
 day: { c: ["#d8ecf7", "#8ccbf8", "#4aa3f2", "#2a7fe6"], e: [3, 12, 30] },

};
/** Функция интерполяции высотных ступеней неба на CPU (для превью-полос и верификации) */
export const skyAt = (p: { c: string[]; e: number[] }, el: number) => {
 const hex = (s: string) => [1, 3, 5].map((i) => parseInt(s.slice(i, i + 2), 16) / 255);
 const lin = (v: number) => (v <= 0.04045 ? v / 12.92 : ((v + 0.055) / 1.055) ** 2.4);
 const srgb = (v: number) => (v <= 0.0031308 ? v * 12.92 : 1.055 * v ** (1 / 2.4) - 0.055);
 const ss = (a: number, b: number, x: number) => { const t = Math.min(1, Math.max(0, (x - a) / (b - a))); return t * t * (3 - 2 * t); };
 const C = p.c.map((s) => hex(s).map(lin));
 const e = [0,...p.e];
 let c = C[0];
 for (let i = 1; i < 4; i++) { const t = ss(e[i - 1], e[i], el); c = c.map((v, k) => v + (C[i][k] - v) * t); }
 return c.map((v) => Math.round(srgb(v) * 255));
};
```
