# Движение камеры, монтаж и анимация походки: эталон против нашей реализации

Единицы измерения: **px = пиксели при эталонном разрешении 720x1280** (для нашего формата 1080x1920 умножайте на 1.5). **f** = кадр при 30 fps.
Эталонная выборка = 20 короткометражных роликов, 32,337 кадров; полоса с вшитыми субтитрами полностью исключена из всех замеров движения камеры.
Наша сборка = файлы `story.ts` / `cast.ts` / `toon.ts` по состоянию на 2026-10-31. Поскольку рендеринг новых кадров при аудите не проводился, наши показатели вычислены **напрямую из кода по тем же математическим формулам**: скрипт `ourcam.py` прогоняет точные структуры `CAMS` + `run()` + `camAt()` (локальная копия, исполняемая через node) через идентичный покадровый расчёт преобразования подобия (similarity fit) и ту же статистическую обработку, что применялась к эталону; скрипт `ourwalk.py` рассчитывает уравнения из `bodyFront` / `bodySide`.

## 0. Ключевой вердикт

1. **Наши переходы камеры — это резкие рывки за 3 кадра; эталонная камера плавно скользит.** В нашей сборке ключевые перемещения на пике дают медиану 115 px/f (доходя до 488) при разгоне (атаке) всего в 3 f. В эталоне пролёты камеры представляют собой симметричное плавное ускорение и торможение (ease-in-out): ~10 f на разгон, ~10 f на затухание, ~23 f общей длительности при медианном пике скорости 14-16 px/f. Концепция «резкого рывка с плавным торможением» ("ease-out burst"), ранее зафиксированная в STYLE_BIBLE.md (и в комментарии заголовка `story.ts`), возникла из-за целочисленной фазовой корреляции, которая не способна различать смещения медленнее ~4 px/f. Это правило ошибочно.
2. **Эталонная камера практически никогда не замирает намертво.** Движение присутствует в 65 % кадров. Даже в спокойных планах камера продолжает медленный наезд (медиана 0.14 %/f). Эффект «ручной камеры» (hand-held float) отсутствует полностью. Удары и сотрясения отыгрываются короткими толчками длительностью 6-7 кадров со сменой знака смещения на каждом кадре.
3. **Персонажи анимированы в каждый кадр (on ones / в единицу).** Никакого дрожания контура (line boil), никакого сжатия и растяжения (squash/stretch), никаких смазов (smears) и зацикленных фоновых покачиваний (idle loops). Вся пластика строится на актёрских акцентах, которые срабатывают за 0-3 f до начала произнесения слова.
4. **Походка упругая, с жёсткой фиксацией стопы.**
 - Вертикальный кач корпуса (bob) составляет 3-7 % от роста фигуры; у нас во фронтальном ракурсе — всего 1.7 %.
 - Наклон корпуса (lean) на каждом шаге качается от 1° до 7°.
 - Один шаг занимает 9-12 f; у нас марш длится 15 f, а шаг туристов растянут на 20-38 f.
 - Опорная нога в эталоне намертво привязана к земле; наши персонажи в боковых ракурсах проскальзывают («катаются на коньках») на 13-60 %.
5. **Моргания частые и проработанные по фазам:** каждые 0.5-2.3 s, длительностью в 4 кадра (полуприкрыто / закрыто / закрыто / полуприкрыто), плюс обязательное моргание на каждой смене эмоции. Наши персонажи моргают раз в 4 s только в два состояния (открыто/закрыто).

## 1. Методика измерений (скрипты в `references/motion/scripts/`)

- **Камера (`cam2.py`, `camstats.py`, `camshape.py`)**
 - Каждый кадр сопоставляется с предыдущим: робастная субпиксельная фазовая корреляция по сетке из 9 тайлов с подбором преобразования подобия (сдвиг translation, зум zoom, крен roll) в разрешении 360x640. Полосы тайлов расположены на высотах 3-29 %, 29-56 % и 80-97 %, чтобы полностью исключить зону субтитров. Тайлы-выбросы отбраковываются.
 - Полученные приращения интегрируются в единую траекторию и сглаживаются фильтром Гаусса с σ = 1.2 f.
 - Итоговая скорость объединяет линейный сдвиг и зум × 734 px (радиус до угла кадра).
 - Классификация состояний: статика (hold) < 0.3 px/f, медленный дрейф (drift) < 2, активное движение (move) ≥ 2.
 - Активные манёвры (bursts) определяются как локальные пики ≥ 6 px/f. Длительность разгона (attack) и торможения (release) замеряется по порогу 10 % от пиковой скорости.
- **Наша сборка (`ours/dump.mjs`, `ourcam.py`)**
 - Функция `camAt()` проецируется через сетку 5x5 точек в плоскости объекта на следующий кадр, после чего обсчитывается тем же алгоритмом.
 - Границы сцен без видимой монтажной склейки (сцены 3-8 и 10 стартуют ровно с кадрирования предыдущего плана) учитываются как непрерывные движения камеры.
 - Реальные склейки (белая вспышка, перекрёстные наплывы) маскируются так же, как монтажные переходы в эталоне.
- **Персонажи**
 - Контрольные раскадровки (contact sheets) отрезков по 2-4 s при 30 fps.
 - Шаблонный трекинг по нормализованной взаимной корреляции NCC (`track.py`) с компенсацией движения камеры по фоновым патчам (`idle.py`, `walkstat.py`).
 - Детекция удержания фаз через межкадровую разность (`uniq.py`).
 - Подсчёт тёмных пикселей в полосе глаз (`blink.py`).
 - Сопоставление площади пятна рта с огибающей громкости голоса (RMS) при сдвигах −4..+4 f (`mouth.py`).

### 5.1 `story.ts`: работа камеры

**а) Интерполяция ключей: плавные пролёты ease-in-out и честные монтажные склейки.** Заменяем кривую चौथой степени `easeOut` внутри `run()`. Саму функцию `easeOut` сохраняем, так как она используется в `snapEnd` для физики оборванного троса. Кроме того, заменяем комментарий в шапке файла (строка 3) на: «непрерывные медленные наезды; симметричные плавные пролёты ease-in-out ~23 f (10 разгон / 10 торможение), пик ~15 px/f при 720p; крупные смены крупности решаются прямыми склейками (cuts)».

```ts
/** эталонная кривая камеры: симметричный smootherstep. Пиковая скорость = 1.875 x distance / dur, поэтому держим dur >= 0.075 x distance (в px при 720p) */
export const glide = (u: number) => { const x = clamp01(u); return x * x * x * (x * (6 * x - 15) + 10); };
type Key = { f: number; dur?: number; cut?: boolean; s: (f: number) => Partial<Cam> & { pos: V3; look: V3 } };
const run = (keys: Key[], f: number) => {
 let cur = full(keys[0].s(f));
 for (let i = 1; i < keys.length; i++) {
 const k = keys[i];
 if (f < k.f) break;
 cur = k.cut ? full(k.s(f)) : mix(cur, full(k.s(f)), glide((f - k.f) / (k.dur ?? 24)));
 }
 return cur;
};
```

Далее применяем таблицу из раздела 2.2 к массиву ключей:
- Перемещения не более чем на половину ширины кадра (≤ 360 px) и с зумом не более 40 % переводятся на `glide` с длительностью `dur` 18-40.
- Всё, что превышает эти пороги, получает флаг `cut: true`. Для пограничных ключей между сценами достаточно просто удалить стартовый ключ, копирующий кадрирование предыдущего плана.

Чтобы самый быстрый кадр пролёта приходился ровно туда, где раньше срабатывал резкий рывок, сдвигайте начало каждого скольжения примерно на `dur/2` раньше. Это художественное решение: точная привязка фазы движения камеры к словам в эталоне не замерялась.

**б) Удержания (Holds): плавный наезд вместо бокового скольжения.** Используйте следующую функцию вместо бокового сдвига `drift(...)` на спокойных ключах:

```ts
/** медленный наезд (dolly) к точке взгляда; размер объекта в кадре растёт примерно на ~rate за кадр.
 * Спокойные кадры эталона: медиана 0.14 %/f, p75 0.34. Акцентные наезды: ~0.6 %/f на протяжении ~35 f (+22 %). */
const push = (pos: V3, look: V3, f: number, f0: number, rate = 0.0025): V3 => {
 const k = (1 - rate) ** Math.max(0, f - f0);
 return [look[0] + (pos[0] - look[0]) * k, look[1] + (pos[1] - look[1]) * k, look[2] + (pos[2] - look[2]) * k];
};
// например, сцена 2: { f: 190, dur: 18, s: (f) => { const look: V3 = [0, 8, 8]; return { pos: push([10, 10.5, -42], look, f, 190, 0.002), look, fov: 42 }; } },
```

Рекомендуемые темпы (`rate`):
- 0.0015-0.0035 на каждом спокойном удержании плана.
- 0.006 на протяжении ~35 f на ударных смысловых фразах: "pride of the whole town", "starts bouncing", реплика про болт, "the best drilled soldiers".

В момент удара наезд обязан прекращаться: ставьте склейку или завершайте действие ключа в кадре контакта. На акцентных ключах задавайте крен `roll` в пределах ±0.06-0.14 rad (3.6-8°) при `dur` ≥ 18. Текущие значения ±0.02-0.06 хорошо подходят для спокойных планов.

**в) Удары: покадрово знакопеременные толчки, отказ от плавающей камеры.** Этот блок полностью заменяет массив `SHAKES`, фоновое покачивание `k` / `n()` и синусоидальную тряску внутри `camAt`:

```ts
// ударные толчки (эталон v14): смещение кадра меняет знак каждый кадр, ~3 px при 720p на единицу амплитуды, затухает за 7 f, крен +-0.23 град на единицу
const KICKS: [number, number][] = [[SNAP, 1], [DROP1, 1.6], [59.79, 0.5], [60.33, 0.5], [61.69, 0.7]];
const kickAt = (t: number) => {

 for (const [t0, g] of KICKS) {
 const n = Math.round((t - t0) * FPS);
 if (n >= 0 && n < 7) a += g * (n % 2 ? -1 : 1) * (1 - n / 7) ** 1.5;

};
export const camAt = (id: number, f: number): Cam => {

 const L = Math.hypot(...d), h = Math.hypot(d[0], d[2]) || 1;

 return {...c, look: [c.look[0] - (d[2] / h) * m, c.look[1] + 0.6 * m, c.look[2] + (d[0] / h) * m], roll: c.roll + a * 0.004 };
};
```

**г) Темп марша (опционально, требует синхронизации со звуковым пайплайном).**
- **Вариант A**, максимально близкий к эталону (2.6 шага/s = 11.5 f на шаг):

 - Все звуки шагов и топота сапог, привязанные к сетке 2 шага/s, потребуется пересчитать под фазы `marchPhase` 0 и 0.5.
 - В сочетании с настройкой ширины шага из п. 5.2 проскальзывание стоп снижается до незаметных ±5 %.
- **Вариант B**: сохранить исторический темп ускоренного марша — 2 шага/s. В этом случае используйте множитель шага `stride ×1.25` при `stomp ≥ 1.35` (проскальзывание ≤ 7 %), а сцену 4 перекадрируйте в ракурс 3/4 спереди, где 28 %-е скольжение стоп при `stomp 1.0` визуально не считывается.

**д) Стабилизация ракурса билбордов (опционально).** Выбирайте фронтальный или боковой вид один раз на весь ключ камеры, а не на каждом кадре, чтобы солдаты не перескакивали из профиля в фас прямо во время плавного наезда:

```ts

export const keyEnd = (id: number, f: number) => {
```

## 6. Топ-5 изменений по визуальному вкладу

1. **Заменить сверхбыстрые пролёты-рывки на прямые склейки, а остальные движения перевести на плавное скольжение** (`story.ts`: `run`, `Key`, `CAMS`; таблица 2.2).
 - Сейчас 13 ключевых переходов пролетают от 0.7 до 3.7 ширины экрана или меняют зум до 275 % за 3-8 кадров со скоростью 79-488 px/f без всякого размытия.
 - В эталоне движения камеры достигают на пике 14-16 px/f и плавно разгоняются/тормозят за ~23 f. Быстрые переброски (≤ 93 px/f) всегда сопровождаются мощным смазом (motion blur).
 - Это главный фактор, выдающий «дешевизну» движения в текущей сборке.
2. **Добавить плавный наезд на каждом удержании плана и наклон камеры (roll) на смысловых акцентах** (`story.ts` CAMS: `push()` вместо `drift()`).
 - Базовая скорость наезда 0.15-0.35 %/f, и 0.6 %/f на протяжении ~35 f на ключевых ударных словах.
 - Повороты крена на 4-8° с плавным скольжением за ≥ 18 f.
 - Полная остановка наезда в момент удара.
3. **Механика походки и марша** (`toon.ts` `bodyFront` / `bodySide`; `cast.ts` `column` / `tourists`; опционально `marchPhase`).
 - Увеличить фронтальный вертикальный кач с 1.7 % до 5 % (марш) и с 1 % до 3 % (прогулка).
 - Ввести цикл наклона корпуса в профиль от 1° до 7°.
 - Привязать ширину шага к линейной скорости, чтобы полностью убрать проскальзывание стоп.
 - Перевести шаг туристов на темп 2.4 шага/s с фазовкой в каждый кадр (on ones).
4. **Моргания и упреждение актёрских реакций** (`cast.ts` `lidAt` / `exprMarch`; `toon.ts` `faceFront`).
 - Интервалы между морганиями 0.5-2.3 s.
 - 4-кадровая структура моргания: полуприкрыто / закрыто / закрыто / полуприкрыто.
 - Обязательное моргание в момент смены эмоции.
 - Сдвиг смены эмоции на 2 f раньше начала звучания слова.
5. **Грамматика ударов и сотрясений** (`story.ts` `camAt` → `kickAt`; `cast.ts` `hammerK`).
 - Заменить 15-кадровое синусоидальное покачивание (6.4 Hz) на жёсткие 7-кадровые толчки со сменой знака на каждом кадре (~3 px при 720p, крен ±0.23°).
 - Для молотка: пауза в замахе, удар за 1 кадр точно на слове, короткая 5-кадровая вспышка.
 - Удалить незаметное фоновое плавание камеры (float).

Следующие по приоритету задачи:
- обездвижить фоновых горожан везде, кроме заданных по таймкоду акцентов;
- зафиксировать ракурс билбордов на время плавных пролётов камеры;
- оставить не более одной быстрой переброски камеры со смазом.

## 7. Ограничения анализа

- **Показатели нашей сборки вычислены аналитически, а не по отрендеренным кадрам.** Параметры камеры в точности соответствуют коду сцен, а метрики походки — математическим формулам отрисовки.
- **Цифры ширины шага и проскальзывания стоп являются приближёнными.** Они выведены из правила нижней точки стопы в `bodySide`; реальное пятно контакта зависит от геометрии эллипса ботинка.
- **Эталонные замеры походки опираются на небольшое число чистых проходок** (ковбой в v04, носильщики в v13, ребёнок в v03), поскольку большую часть хронометража эталона занимает актёрская игра на месте, а не ходьба. Углы сгиба ног оценены визуально по листам раскадровок. Амплитуду отмашки рук измерить не удалось.
- **Экспертные решения (не прямые замеры):**
 - сдвиг старта плавных пролётов на `dur/2` раньше;
 - границы временных окон для реакции массовки;
 - разброс фаз наклона головы у сидящих на берегу;
 - сохранение темпа 2 шага/s в Варианте B.
